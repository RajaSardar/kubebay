AI triage adds a **Triage** tab to pods. It gathers the evidence about one pod, asks a model what's wrong, and shows each finding beside the evidence it cites. It's off until you turn it on for a cluster.

## Turning it on

In **Settings → AI incident triage**:

1. Tick the clusters whose pods get a Triage tab.
2. Set the **Endpoint**, such as `https://api.anthropic.com`, and the **Model**.
3. Add an **API key**. **Save key** stores it in your OS keychain. Without a keychain, set `KUBEBAY_TRIAGE_API_KEY` in Kubebay's environment instead. The key is never shown again, never stored in Kubebay's settings, and **Remove key** deletes it.
4. Click **Turn on**.

## Using it

Open a pod's drawer, then **Triage**.

1. **Gather evidence** collects a bounded bundle: the pod, its owners, warning events, recent rollouts and logs. Credentials in it are masked.
2. Kubebay shows **What would be sent**: the endpoint, the model, about how many tokens, how many values were masked, and whether logs were cut to fit. **Copy evidence** copies it, if you'd rather paste it somewhere yourself.
3. Nothing has been sent yet. **Send to *model*** makes exactly that request, once.
4. The answer lists likely causes, each citing the evidence it's based on, then **Next steps, for you to review**. If the evidence doesn't support a cause, it says so, and says what evidence would help.

The model only reads. Nothing in the cluster changes. Every preview and every send is written to the [Audit Log](/docs/audit-log/).

> The answer is generated by a model from the evidence shown. Check it before you act on it.

## Where it's available

Triage is part of Kubebay on your own machine. It isn't available when the engine runs in a cluster or with OIDC sign-in.
