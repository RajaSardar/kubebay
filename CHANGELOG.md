# Changelog

All notable changes to Kubebay are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows
[SemVer](https://semver.org/) once v1.0 is reached (pre-1.0: minor = breaking, patch = features/fixes).

## [Unreleased]

### Added
- **Extensions: your own columns and row actions**: `~/.kubebay/extensions.yaml` adds table columns (a JSONPath per resource) and row-menu actions to any resource's table, Pods included. A link action opens in the browser with the row's values percent-encoded into its path and query; its host is always the one you wrote. A command action opens Terminal on the row's cluster and types the command at the prompt without pressing Enter, with every value quoted as one argument (checked against bash, dash, zsh and fish with hostile names and annotations). Values with control or direction characters aren't typed, and a placeholder inside quotes is refused when the file loads. Placeholders: `{{name}}`, `{{namespace}}`, `{{kind}}`, `{{context}}`, `{{label:KEY}}`, `{{annotation:KEY}}`; an action can be limited to some contexts. Kubebay only reads the file, again on each Reload, so edits need no restart. Settings → Extensions shows what loaded and why any entry was skipped. Command actions need the local shell and a shell Kubebay quotes for (sh, bash, zsh, dash, ksh, fish). Extensions are off in in-cluster and OIDC modes. Resource-table JSONPath now also reads `[N]` indexes and `\.` inside keys. See `docs/EXTENSIONS.md`
- **Export a findings report**: the RBAC page's "Export report" saves every finding Kubebay's detectors have for the cluster as SARIF 2.1.0 (for code-scanning tools), JSON or Markdown. It covers attack paths, RBAC findings (system bindings left out, as on the page), API versions an upcoming release removes, single points of failure, pods no NetworkPolicy selects, Secrets read into environment variables, default-ServiceAccount token mounts, and namespaces where nothing enforces image signatures, each with its CIS and ATT&CK control IDs. The report names the cluster, the time and the Kubebay version (a new token-protected `/api/version`). The objects only the export needs (PodDisruptionBudgets, EndpointSlices, served API versions) load only while its dialog is open. The file is saved on this machine and sent nowhere
- **Rancher-aware clusters**: a context that goes through Rancher's cluster proxy (`https://<rancher>/k8s/clusters/<id>`) gets a "Rancher" badge on the cluster list, whatever its name, and an "Open in Rancher" row action that opens that cluster in the Rancher dashboard. Authorized Cluster Endpoint contexts, which reach the cluster directly, aren't labelled. The `rancher-desktop` context is badged "Rancher Desktop". In a cluster with Rancher projects, the namespace filter groups namespaces by project (`field.cattle.io/projectId`), with the rest under "Not in a project". Kubebay never uses a Rancher API token: the kubeconfig stays the only credential
- **Keyless image signatures are verified, and the signer is named**: the running-image signature check (RBAC page card and the workload, pod drawer Signatures tabs) now checks a keyless cosign signature the way cosign does against Sigstore's public instance, instead of leaving it to the admission controller. The Rekor entry's signed timestamp must verify with a Rekor key in Sigstore's trusted root, the entry must record this signature, certificate and payload, the certificate must chain to Fulcio at the time Rekor logged it and carry an SCT from a known CT log, and the signature must verify. The signer (email or workflow URI) and OIDC issuer are shown. They're then matched against the keyless identities in the cluster's Kyverno verifyImages attestors (subject/issuer, regexps, `*` wildcards) and Sigstore ClusterImagePolicy keyless authorities: a match is "verified by <policy>", a signer no identity allows is "verification failed" with who signed, and with no policy identity the verified signer is still shown. Identities that trust their own Fulcio roots or Rekor log are reported as not judged here. Sigstore's trusted root is fetched only when a keyless signature turns up, through TUF (go-tuf, starting from the root sigstore-go ships), reused for a day, and kept in `~/.kubebay/sigstore` so a check offline uses the last verified copy. With no copy and no network the signature is reported as not checked, and that answer isn't cached. OCI 1.1 Sigstore bundles are still found but not verified
- **When it last rolled out**: a Deployment's Summary tab says how old its current revision is and how many rollouts the last 7 days had, rollbacks included ("Revision 4, rolled out 3d ago · 2 rollouts in the last 7 days"), with a button to the Rollout tab. It reads the ReplicaSets the cluster keeps, so it needs no recording. A rollback reuses an older ReplicaSet, so it is named as a rollback rather than given an age, and when ReplicaSets pruned by `revisionHistoryLimit` hide part of the week the count says "at least"
- **Why a workload keeps breaking**: with history recording on, each broken hour now keeps its reason (CrashLoopBackOff, OOMKilled, ImagePullBackOff…), and after a recorded week the workload drawer's 7-day chip says so: "Broken in 9 of 166 recorded hours, on 5 of 7 recorded days, mostly: keeps crashing on start". It names a reason only when one is behind at least half the broken hours, and never a vague one (not ready, pending)
- **Assistants can propose changes; you approve them**: a new "Let assistants propose changes" setting under AI assistants (off by default) adds the MCP tools `propose_change` and `get_proposal_status`. A proposal is a strategic merge patch to a Deployment, StatefulSet, DaemonSet, CronJob, Service or Ingress in scope (`spec` and metadata labels/annotations only). Kubebay dry-runs it, changes nothing, and opens a dialog showing who proposed what, why, and the exact diff, with Approve and apply, Reject or Decide later. Approving applies exactly that diff as field manager `kubebay-mcp`, and only if the object hasn't changed since; otherwise the proposal goes stale. Proposals expire after 5 minutes. Scope is checked again at approval, only the Kubebay window can approve (never the MCP token), turning MCP or proposals off rejects whatever is waiting, and every step is audited. The assistant's copy of the diff has env values redacted
- **AI incident triage, step 2: Send**: when a key is set, the pod Triage tab's review pane has a "Send to <model>" button that makes exactly the request shown, once, with the Anthropic Go SDK. The engine reads no credentials or endpoint from its environment beyond the key it names, so the call goes where the preview says. The answer comes back as structured JSON: a summary, findings rated likely, possible or unlikely, each citing bundle sections by ID, next steps as text only, and what evidence is missing. Kubebay removes citations to sections that aren't in the bundle and hides findings left with none, and says how many it hid. Each finding shows the sections it cites. A refusal is shown as one, not as findings. Triage asks for `high` effort on models that take it. On Anthropic's own endpoint, for Claude Opus 5.5, Opus 5, Fable 5.1 and Sonnet 5.5, it asks for server-side refusal fallbacks (`fallbacks: "default"`), and the tab names the model that answered. A preview can be sent for 10 minutes, and Send checks again that triage is on for the cluster and the endpoint and model haven't changed. A failed send can be retried. Each send is audited as `triage:send` with the outcome and token counts
- **AI incident triage, step 1: consent and the review pane**: Settings → AI incident triage is off by default. It turns on per cluster, with a configurable endpoint (Anthropic's Messages API, or a proxy that speaks it over https; http only on this machine) and model. The API key goes to the macOS Keychain or libsecret, or comes from `KUBEBAY_TRIAGE_API_KEY` / `ANTHROPIC_API_KEY`, and is never written to settings. Pods in allowed clusters get a Triage tab that gathers a bounded evidence bundle: the pod and its owners, container states with the last exit, Warning events for the pod and its owners deduped with counts, the Deployment's recent revisions, and logs, with a restarted container's previous run first. The tab shows the exact request, with credentials masked and logs cut to about 12k tokens. Nothing is sent yet; the bundle can be copied. Each preview is audited. Not available in in-cluster or OIDC mode
- **MCP `get_logs` masks credentials** (tokens, keys, passwords in URLs and `name=value` pairs) with the same pass triage uses
- **Find AKS clusters**: the cluster list's Kubeconfig sources dialog also lists the AKS clusters your own `az` can see, in every resource group of the subscription you pick (az's current one first), and imports one with a click. Only clusters that sign in with Microsoft Entra ID import. The file Kubebay writes, `~/.kubebay/discovered/aks-<subscription>-<group>-<name>.yaml` (0600, context `aks_<first 8 of subscription>_<group>/<name>`, shown with the AKS badge and its cluster name), signs in with `kubelogin get-token --login azurecli`, so tokens come from your `az login` and no client certificate or token is stored. Clusters with local Kubernetes accounts are listed with the reason and no Import button. Kubebay reads the API server and CA through `az rest` (the same `listClusterUserCredential` call), not `az aks get-credentials`, which can run `kubelogin convert-kubeconfig` on your own kubeconfig. A cluster you already fetched with `az aks get-credentials` is recognised by its API server. Private clusters are marked. It's user-triggered only, desktop only, and az's errors are turned into the fix (sign in, the role it needs, an unregistered provider)
- **Find GKE clusters**: the cluster list's Kubeconfig sources dialog also lists the GKE clusters your own `gcloud` can see, in every location of the project you pick (gcloud's default first), and imports one with a click. The import writes `~/.kubebay/discovered/gke-<project>-<location>-<name>.yaml` (0600), named `gke_PROJECT_LOCATION_NAME` like `gcloud container clusters get-credentials`, signing in with `gke-gcloud-auth-plugin`, never a static token. It's user-triggered only, desktop only, and gcloud's errors are turned into the fix (log in again, enable the Kubernetes Engine API, the missing permission)
- **AI assistants (MCP)**: Settings → AI assistants lets Claude Desktop, Claude Code or another MCP client read the clusters you pick, whole clusters or named namespaces. It's off by default and read-only (list, describe, logs, events, manifests, cluster health). Secrets and ConfigMap contents are never shown, and environment values are redacted. The card gives the Claude Desktop config and the `claude mcp add` command; both run `kubebay-engine mcp-stdio`, which reads a token Kubebay keeps in `~/.kubebay/mcp.json` (0600) and replaces when you turn MCP on or rotate it. Turning it off revokes the token. Every call goes to the audit log, the card lists recent ones, and the sidebar shows "AI access on" while it's on. Not available in in-cluster or OIDC mode
- **Overview: why it fails, and since when**: the top five Needs attention rows show the worst pod's last log line (from the crashed run when it has restarted), and a workload's Summary tab shows its warnings over the last hour as 5-minute bars with whether they are new, started a while ago or have gone on all hour. With history recording on, the Summary tab also says how many recorded hours of the last 7 days the workload was broken in ("Broken in 9 of 131 recorded hours, on 4 of 6 recorded days"); the engine records one sparse line per broken workload per hour
- **Scale and restart from the table**: Deployment and StatefulSet rows get Scale… and Restart… in their row menu (DaemonSets get Restart…), each a small dialog that warns when Argo CD or Flux owns the workload and shows a policy rejection in place. `Modal` gains `placement="center"` for such dialogs
- **Faster, friendlier resource tables**: the filter matches every column (Pods: name, namespace, node, IP and status) and ignores case; the count reads "3 of 340" while filtered; `/` focuses the filter, ↑/↓ or j/k move, Enter opens, x selects, Esc clears; the sort is remembered per table; ages show the exact time on hover; Pods gets a row menu (Logs, Shell, Edit YAML, Copy name, Delete) and clickable namespace pills; the + button opens Create Resource on that kind's template
- **Loading states**: a new helm loading icon and `Spinner`, shown while switching clusters; lists load as skeleton rows under their real headers, drawers as skeleton lines, lazily loaded pages as a skeleton page, and tables show a thin progress bar while cached rows refresh
- **`Row`, `Stack`, `DisclosureButton` and `ChoiceCard` in `@kubebay/ui`**: every flex layout in the app uses `Row` or `Stack` with gaps from the spacing scale; sidebar groups announce whether they are expanded and theme cards which one is chosen to screen readers
- **Shared shell components in `@kubebay/ui`**: `StatusPill` + `phaseTone()`, `Tabs`, `NavItem`/`NavSection` + `navItemClass()`, `TextField`, `Select`, `Kbd`, `PageHeader` (with `level` and `live`) and `ContextMenu`. Their styles now live in the package (#12)
- `--kb-on-danger` token in every theme for labels on danger fills (#12)
- **`Drawer` and `Modal` in `@kubebay/ui`**: the Pod, Helm release, Helm chart and resource drawers share one component that closes on Escape (not while you type in a field, the YAML editor or the terminal) and returns focus to where it was; the cluster icon picker is a `Modal` that keeps focus inside until it closes
- **`IconButton`, `SegmentedControl` and `Badge` tones `warn`/`info` in `@kubebay/ui`**: close, pop-out, star and row-menu buttons share one look and always carry an accessible label; the Settings display options and the Workloads and Network Policy view switches are keyboard-navigable radio groups; hand-written tab rows (Pod panel, Helm, cluster icon picker) use `Tabs`
- **`DataTable` and table primitives in `@kubebay/ui`**: every table in the app (resources, pods, Helm, ArgoCD, audit log, port forwards, network policies, cluster picker, cost and right-sizing panels) now shares the ResourceTable design. Also new: `EmptyState`, `InlineBanner`, `KubebayMark`
- `docs/DESIGN_SYSTEM.md` and a CLAUDE.md rule: all UI is built from `@kubebay/ui`, enforced by tests
- **Karpenter safe editing**: an Edit affordance on each NodePool card shows a blast-radius impact banner (nodes/pods/namespaces backed by the pool, spot count, and real PodDisruptionBudget coverage via Kubernetes label-selector matching) and requires typing the NodePool's name to confirm before applying any of three eviction-causing edits (shrinking `spec.limits`, lowering a disruption budget's `nodes` value, or switching `consolidationPolicy` to `WhenEmptyOrUnderutilized`)
- **KEDA ScaledObject wizard**: an "Add ScaledObject" flow in the Autoscaling tab generates a manifest for cron, CPU/memory, or Prometheus triggers, previews it with a live diff, and dry-runs/applies it — always created paused, with scale-to-zero (`minReplicaCount: 0`) gated behind typing the workload's name to confirm, and blocked outright if an HPA already targets the same workload. The Prometheus trigger suggests in-cluster Service candidates for `serverAddress` rather than reusing Kubebay's local Prometheus proxy URL, which resolves to a different address entirely
- **The desktop window follows the theme**: the title bar and the window behind the page take the chosen theme's appearance and colour (or follow macOS for System), and the next launch opens in them instead of flashing the OS default

### Changed
- **Building the engine needs Go 1.24 or later** (was 1.22, out of support since February 2025). `go.mod` asks for Go 1.24 at minimum, which the Anthropic Go SDK needs for AI triage, and names Go 1.26.9 as the toolchain, so CI, release and Docker builds use a supported compiler. `make build` still uses whatever Go you have installed (`GOTOOLCHAIN=local`), so install Go 1.24 or later first
- Removed about 800 lines of unused styles and two unrouted pages (the old Home and Overview)
- **Every theme meets WCAG AA**: text reads at 4.5:1 or better on every surface, status pills and button labels reach 4.5:1, and focus rings are solid and at least 3:1. Dawn HC and Dusk HC reach 7:1 for body text with 3:1 control borders. Hues are kept; only lightness moves. Visible changes: Dusk primary buttons use a dark label on cyan, Dawn's accent is a deeper blue (`#0065c9`), VS Code Dark+ uses a lighter blue (`#31a6ff`), and Nord's error red is a pale rose (`#e6c1c4`) (#12, this release)
- The shell renders every page header, toolbar input and select, keycap and sidebar link through `@kubebay/ui`, so the package is the single source of truth for that markup
- Settings theme swatches match each theme's colours
- Ghost and danger buttons match the design system everywhere (an `app.css` override had given them a weaker border and smaller text); the cluster picker's search, table, status and provider badges and row menu use the shared components; provider badges are neutral instead of hand-picked hues that failed contrast in light themes
- Cluster avatars pick black or white initials by contrast with their colour
- **"System" theme follows the OS contrast setting**: with "Increase contrast" on, it picks Dusk HC or Dawn HC
- **Pending has its own colour**: Pending pods use each theme's info hue instead of the warning orange, so they no longer read as warnings

### Fixed
- **A Deployment's Rollout tab finds its ReplicaSets again**: the drawer's copy of an object had its `uid` and creation time stripped like the YAML editor's, so the Rollout tab always said "No ReplicaSets found", the Timeline had no rollout revisions, and Summary's Created read "–". Only the editor's YAML leaves them out now
- **Dialogs say what they are**: `Modal` takes a `title`, shown as the dialog's heading with a Close button beside it, and centred dialogs taller than the window scroll inside instead of running off it. Configure Prometheus, Scale and Restart, Remove from list and Kubeconfig sources use it; the first had no visible heading at all
- **Configure Prometheus dialog**: the URL field, Cancel and Save show at once instead of waiting behind a spinner that never ended when the cluster's Services could not be listed. It no longer connects a cluster just to look for services, and is not offered for a broken kubeconfig entry. It opens on the URL already set; saving it empty goes back to the default. It lists the Prometheus server first, without Grafana, Alertmanager or exporters (at most four). A service on port 80 gets `localhost:9090` and `port-forward 9090:80`. Enter saves, the engine's own save error is shown, and the dialog is wide enough for a URL and its port-forward command
- **Clusters page**: it no longer opens blank (`HEADERS is not defined` after the v0.5.0 version bump), and its row menu items work again. A pressed row's scale effect moved the menu mid-click, so no item ran; `ContextMenu` now renders into `document.body`, as `Modal` does
- Tables sorted counts as text, so a Job with 10 failures sorted below one with 9 (also Restarts, node Pods, event Count). Every table now sorts numbers as numbers and names naturally (pod-9 before pod-10), ignoring case
- The Pods table mounted every row (5,000 pods meant 5,000 rows); it now renders only the rows in view, like the other tables. Every table also estimated rows 6px too short, which left the active row half off-screen after a keyboard move and made the scrollbar jump
- Pods' CPU and memory bars measured every pod against 1 core and 1 GiB, and memory was always drawn in the warning colour. Bars now measure against the pod's own limit (warning at 80%, error at 100%), or its request when it has no limit, and the tooltip says which
- Ages in tables went stale: a pod created "5s" ago still read "5s" a minute later, because rows only re-render when their data changes. Age cells now keep counting, from one shared clock
- Tables could stay on their loading skeleton forever on a fast cluster, and a table could briefly show another resource's rows (StatefulSets showing Deployments): stream frames were handled out of order
- Pods never showed "live" and did not load CPU/memory on a second visit
- The + button on resource tables did nothing; the row menu's "Edit YAML" opened the summary
- The Create Resource dry-run toggle label used an undeclared colour token; it now uses the muted text colour
- Every size, radius, animation duration and stacking layer in the app comes from the design tokens, so the command palette, context menus, drawers and dialogs always stack in the same order
- Borders, focus halos, text colour and backgrounds missing in the Network Policy view, cluster picker and cluster detail drawer: six undefined `--kb-*` variables now point at real tokens (#12)
- Cluster-picker nav highlight and engine-status dot follow the theme instead of fixed colours (#12)
- ArgoCD sync and health pills had no background or border (their colour was built as invalid CSS)
- Two notices styled with an `info-banner` class that had no CSS now render as proper banners
- Light-theme users no longer see a dark frame on launch: the saved theme is applied before first paint
- Text inputs and selects have a visible edge in every theme (3:1, WCAG 1.4.11) via a new `--kb-border-control` token; before, it measured 1.1–1.8:1
- Focus rings, selected rows and status dots stay visible in Windows High Contrast (forced colours)
- **Full design-system audit across all 12 themes** (every component rendered and measured, plus the cluster catalog and Settings in the running app):
  - Table loading states drew nothing: skeleton blocks were inline spans with no size inside table cells. They are now visible blocks on every ground
  - Pill, badge, active-segment and palette text fell below 4.5:1 on canvas, raised and inset grounds and on selected rows in up to nine themes. Tints are lighter, pill text is adjusted per theme, and Dawn, VS Code Light+, GitHub Light and Nord have a slightly deeper accent
  - Cluster avatars: the AWS preset (`#F90`) and unknown clusters showed white labels on light colours (1.9:1); inactive clusters in the strip were faded to 32%, taking labels to 1.3:1. Labels pick their colour correctly and inactive avatars are desaturated instead of faded
  - The active theme card hid its keyboard focus ring; a namespace pill on a selected row stacked a second tint; the palette's "syncing…" faded to unreadable
  - Dracula's muted text was the accent purple (looked like links); Nord's error was a pale rose indistinguishable from its success and warning; VS Code Dark+ warning sat 17° from its error
- The cluster icon picker opened half off-screen and under the sidebar: the translucent cluster strip trapped its fixed position. Modals now render into the page body
- Text that was unreadable in light themes: the CRD "ns" badge, the Normal event badge, the active CRD tree row and the active favourite used the white on-accent label colour on a pale tint; they now use the accent. A contrast test stops it recurring
- Pod history graphs use the theme's chart colours (`--kb-chart-1…5`, 3:1 on every ground) instead of one fixed palette for all 12 themes
- In Dawn and VS Code Light, the ok, warn and error colours now read at 4.5:1 on inset fields too
- Code editors use Monaco's high-contrast themes in Dawn HC and Dusk HC
- Favicons, the PWA icons and the macOS and Windows app icons use the cyan-to-green Kubebay mark (they still had the old blue start colour); the website favicon, nav and footer show the mark instead of a separate K logo
- The website uses the app's design tokens (`tokens.css`) for colour, radii and motion instead of its own copies
