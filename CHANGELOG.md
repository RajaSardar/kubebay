# Changelog

All notable changes to Kubebay are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows
[SemVer](https://semver.org/) once v1.0 is reached (pre-1.0: minor = breaking, patch = features/fixes).

## [Unreleased]

### Added
- **Pod drawer: labels, env sources and Secret/ConfigMap references** (backlog 62). A pod's Summary shows its **Labels**, every environment variable (it stopped at 20), each container's **Environment from** (`envFrom` Secret and ConfigMap sources with prefix and optional), and **Secrets** and **ConfigMaps** sections listing everything the pod refers to (env, `envFrom`, volumes, projected volumes, image pull secrets) as links with where each is used. References only: Secret values still appear only through the existing **Show** with its audit.
- **Service endpoints** (backlog 64). The Services list has an **Endpoints** column, ready over total addresses from the EndpointSlices (`2/3`, red `0/0` when a selector matches nothing, a dash for ExternalName), and the Service drawer's Summary an **Endpoints** section: each address with Ready or Not ready, the ports, the node, and the target Pod as a link to its drawer. Not run against a live cluster.
- **Labels column** (backlog 65). Pods and every other resource list have a **Labels** column in the column chooser, hidden by default: the first three labels as chips, +N for the rest, the full list in the tooltip. It sorts, and filters as `labels:tier=front`; `label:app=web` already filtered on labels and still does.
- **Resizable sidebar and drawer** (backlog 68). Drag the sidebar's right edge, or a drawer's left edge, to widen or narrow it. Both edges are keyboard separators: <kbd>←</kbd>/<kbd>→</kbd> move 16 pixels (<kbd>Shift</kbd> 64), <kbd>Home</kbd>/<kbd>End</kbd> go to the limits, a double-click restores the default (210 pixels for the sidebar through `--kb-sidebar-w`, 820 pixels or three quarters of a narrow window for the drawer). The sidebar runs 160 to 420 pixels and collapses when dragged well past the narrow end; the drawer runs 360 pixels to 90% of the window. Widths are saved in this browser (`kb.sidebar.width`, `kb.drawer.width`) and read when a window starts, like the other layout settings, so another open window doesn't move under you. The in-drawer split divider is unchanged. New in `@kubebay/ui`: `ResizeHandle` and `useStoredWidth`.

### Changed
- **Restart asks once more** (backlog 71). Every Restart (a workload's row menu, the drawer's actions bar for Deployments, StatefulSets, DaemonSets and Rollouts, and **Restart** on the Rollouts page) now needs a second step. In the drawer and on the Rollouts page the button turns into **Confirm restart?** and restarts on the second click, and the row's **Restart…** dialog turns its button into **Confirm restart?** too, still with **What this affects** and the GitOps warning. On a production-looking cluster the Rollouts page still asks its production question after that. A guard test fails if any code that restarts reaches the API without this step.

### Fixed
- **NodePort Services showed as ClusterIP with no ports** (backlog 66). Services, Endpoints and Ingresses were streamed as metadata only, which strips `spec`, so the Services list's Type, Cluster IP and Port columns (and `type:NodePort` in the filter) had nothing to read, Endpoints counted 0 and Ingresses had no Class or Hosts. They now stream in full. Not run against a live cluster.
- **Scale shows there is something to apply and moves faster** (backlog 69). When **−** or **+** changes the replica count, **Apply scale** turns solid and an **Unsaved** badge shows beside the count, and both go when the count is back to the current one. The count is now a number box you can type into, with **−10**, **−5**, **+5** and **+10** buttons, <kbd>Shift</kbd>-click on **−**/**+** (or <kbd>Shift</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd>) for steps of 10, and a floor of 0. The drawer and the row's Scale dialog share it, and the **What this affects** preview still shows for a scale down.
- **Resource tables always have a sideways scrollbar** (backlog 67). The operating system's own scrollbar is 4px thin and, on macOS, hidden until you scroll, so a wide Pods table (for example after a filter left a few rows) looked as if it would not scroll sideways. Every table now has a bar under its viewport, drawn by Kubebay: it stays at the bottom however far down the rows go, shows only when the table is wider than the window, and takes a drag, a click to page, and <kbd>←</kbd>/<kbd>→</kbd>/<kbd>Home</kbd>/<kbd>End</kbd> when focused.

## [0.8.2] - 2026-11-24

v0.8.1 was tagged but never published (its macOS build ran out of memory), so everything it held ships here.

### Added
- **One-line install on Linux** (backlog 58). `curl -fsSL https://github.com/RajaSardar/kubebay/releases/latest/download/install.sh | sh` installs the engine for Linux or macOS on x86_64 or arm64 into `~/.local/bin` (`/usr/local/bin` as root), says when that folder isn't on `PATH`, and prints how to start it and where the token is. `sh -s -- --desktop` installs the Linux desktop app instead: the `.deb` through `apt-get`, so apt installs WebKitGTK and GTK with it, or with `--appimage` (or where there is no apt) the AppImage as `kubebay-desktop` with an applications-menu entry. It runs under POSIX `sh` (dash on Ubuntu), works with `curl` or `wget`, checks every download against the release's SHA-256 and, with `cosign` installed, its signature before installing anything, refuses a release with no checksum unless `KUBEBAY_INSTALL_UNVERIFIED=1`, and takes a version (`sh -s -- v0.9.0`). Each release publishes it next to `install-mac.sh`. On arm64 Linux `--desktop` says the desktop app is x86_64 only and points at the engine.
- **An Install section in the README** for macOS, Linux, Windows, Docker, Helm and building from source.
- **Add sidecar** (backlog 56). A Deployment, StatefulSet, DaemonSet or CronJob drawer has **Add sidecar**: pick **Log shipper** (busybox `tail -F` on a shared emptyDir), **Debug toolbox** (netshoot, `sleep infinity`), **Cloud SQL proxy** or **Custom**, and edit the name, image, command, args, env, ports, requests and limits, mounts of existing volumes or a new shared emptyDir. On Kubernetes 1.29+ it is a native sidecar (an init container with `restartPolicy: Always`) unless you pick a regular container. **Preview** dry-runs it and shows the diff; **Add sidecar** then sends a strategic merge patch that only appends, after the production confirmation, with the rollout restart warning, **What this affects** and the GitOps warning. Duplicate container names are refused. Audited as `add-sidecar`. Not run against a live cluster. Spec in `docs/ADD_SIDECAR.md`.
- **Service map: observed traffic on All namespaces, and ReferenceGrant checks** (backlog 39 follow-up). With **All namespaces** picked, **observed traffic (Prometheus)** now runs one cluster-wide query per metric (`istio_requests_total`, `nginx_ingress_controller_requests`), grouped by source and destination namespace and workload, and draws calls from one namespace to another as observed lines between the groups, still labelled with the rate, the PromQL and the time. Each query keeps the 500 busiest series and says when there were more; nodes past the 400-node limit draw no traffic. Where the Gateway API ReferenceGrant CRD exists, a route `backendRef` to a Service in another namespace that no ReferenceGrant there allows shows a finding, "HTTPRoute X in A points at Service Y in B, but no ReferenceGrant there allows it". Not run against a live Istio, ingress-nginx or Gateway API install.
- **Helm store: README tables, per-repo Refresh, Compare versions** (backlog 11 follow-up). A chart's README now renders GitHub pipe tables, with their column alignment and wrapping cells, as the design system's table, still built from elements with no HTML from the README. With one repository picked, **Refresh** re-fetches only that repository's index (same address checks; a new index replaces the cached one only once Helm has validated it) and the toolbar says when its index was last fetched. A chart's page has **Compare versions**: a side-by-side diff of two versions' default `values.yaml`, starting on the installed version against the newest, each archive fetched through the guarded path. **About** marks a release whose chart version isn't in this repository's index; Helm releases don't record their repository, so **Installed** still goes by chart name.
- **Search all clusters** (backlog 12 follow-up). A new page in the sidebar's Tools, also opened from the ⌘K palette's **Search all clusters for "…"**, finds objects by name, or by kind and name (`deploy api`, `svc:web`), in every cluster at once. Each result shows its Cluster, Kind, Namespace and Name, and clicking one opens its cluster and the object's drawer. Connected clusters are searched as you type, from memory and the engine's search index. Clusters that aren't connected are searched only after you click **Also search N disconnected clusters**. They are never connected: the engine's `POST /api/search/clusters` lists only their names (metadata-only, paged LISTs) for Pods, Deployments, StatefulSets, DaemonSets, Jobs, CronJobs, Services, Ingresses, ConfigMaps and Namespaces, as the signed-in OIDC user. It searches at most 10 clusters at a time and 200 per request, gives each cluster 12 seconds and up to 5,000 objects per kind, and keeps the names for 60 seconds. A kind you may not list, or a cluster that can't be reached, becomes a note on that cluster. The page lists the best 200 results and says how many there were. Custom resources in clusters that aren't connected aren't searched. Not run against a live fleet.
- **Best practices: framework scores and Fix** (backlog 36 follow-up). Beside the overall score, **By framework** shows a score for Security, Reliability, Disaster recovery and Platform, and one for the CIS-referenced checks (labelled as not a CIS compliance score); Ignored checks stay out of every score. Failing PodDisruptionBudget, NetworkPolicy, Pod Security label and default ServiceAccount token checks have a **Fix** that opens generated YAML (a PodDisruptionBudget per workload, a default-deny ingress NetworkPolicy, `enforce: baseline` labels, `automountServiceAccountToken: false`) in a dock **New resource** tab to review, dry-run and apply; nothing is applied by itself. Create Resource gains a PodDisruptionBudget template. The four CIS tags were re-checked against kube-bench's v1.8 and v1.10 control ids and are unchanged. Not run against a live cluster.
- **Blast-radius preview for scale downs and bulk deletes** (backlog 12 follow-up). Scaling a Deployment or StatefulSet down to a non-zero count (the row's Scale dialog, and the drawer under **Apply scale** once **−** goes below the current count) shows **What this affects**: the Pods that would go (a StatefulSet's highest ordinals; for a Deployment the controller's likely picks), Services with fewer ready endpoints as `web (5 → 2 ready)` or none, a PodDisruptionBudget left below its `minAvailable`, and an HPA that would fight the change (with its `minReplicas` when that is above the new count). A multi-select delete in a resource table now shows one aggregate preview across the whole selection, with the number selected, capped name lists and totals, namespaced names when the selection spans namespaces, and Services judged against the selection as a whole.
- **Fleet summary on the Clusters page** (backlog 37, summary tier). **Show fleet summary** reads the version and ready nodes over total for each cluster on screen that isn't connected. It opens no streams and doesn't count against the warm-cluster limit. A warning pill marks clusters with nodes that aren't ready, and the header adds a line such as "2 nodes not ready in 1 cluster". The engine's `POST /api/clusters/summary` answers from a 60-second cache and checks at most 10 clusters at a time, 200 per request, 12 seconds each. It never waits on a cluster: one that is still being checked comes back pending.
- **Argo Rollouts: Pause, Resume and Skip step** (backlog 52 follow-up). The Rollouts page and a Rollout's drawer have **Pause** (`spec.paused: true`, like `kubectl argo rollouts pause`), **Resume** in its place when you paused it (`spec.paused: false`), and, for a canary short of its last step, **Skip step** (`status.currentStepIndex` + 1, like `promote --skip-current-step`, pinned to the `resourceVersion` it was read from where known). The `status` fields of Promote, Promote fully, Skip step, Abort and Retry now go to the Rollout's status subresource, which the API server would otherwise ignore them on since Rollouts v1.0, falling back to the Rollout itself where there is none: `PUT /api/yaml` takes `subresource: "status"` with `mode: "merge"` and refuses any other subresource. A Failed or Error Argo Workflow shows its `argo retry` command to copy; Retry stays out of the app because it needs Argo's server. Not run against a live Argo install.
- **Restart in the Rollout drawer.** An Argo Rollout's drawer has a Restart button beside the replica stepper. It sets `spec.restartAt`, the way the Rollouts page's Restart does, so the controller replaces the pods following the Rollout's strategy.
- **Owner column** (backlog 54). Pods and ReplicaSets show **Owner**: the controller from `ownerReferences` as `Kind/name`, linking to its drawer (a Deployment's pods show the Deployment through their ReplicaSet; StatefulSet, DaemonSet, Job, Argo `Rollout` and a static pod's Node are shown directly; a bare object shows —). Filter with `controller:statefulset`. Every other resource list has it in the column chooser, hidden by default (not on Events). A column added after a layout was saved now follows its own default instead of always showing. Research in `docs/OWNER_COLUMN.md`.
- **Argo Rollouts dashboard** (backlog 52, Rollouts part). **Rollouts** in the sidebar's Tools, listed only where the `rollouts.argoproj.io` CRD is served, shows each Rollout's phase, canary or blueGreen strategy, step N of M, canary and stable weight, desired, updated, ready and available replicas, stable and canary ReplicaSet revisions with images, pause reason and owned AnalysisRuns with their phase. **Promote**, **Promote fully**, **Abort**, **Retry** and **Restart** patch the Rollout through the audited YAML apply path, with a production confirmation. The patches follow the kubectl-argo-rollouts plugin from memory and have not been run against a live cluster; skip-step and pause are not offered.
- **Argo Workflows and Argo Events pages** (backlog 52, part). **Argo Workflows** (`/argo-workflows`) lists Workflows with a phase pill, progress, duration and start time, with tabs for WorkflowTemplates, ClusterWorkflowTemplates and CronWorkflows (schedule, time zone, next run, suspended state). A workflow opens to its node tree (type, phase, message, and a link to the pod that ran each step). **Stop**, **Terminate**, **Suspend** and **Resume** patch `spec.shutdown` / `spec.suspend`; **Resubmit** creates a new Workflow from the old spec with `generateName`; each asks for a second click, is audited and uses your own permissions. Retry is not offered (Argo rewrites node status for it). **Argo Events** (`/argo-events`) is a read-only inventory of EventSources (declared event types), Sensors (dependencies and what each trigger creates, linked to the Workflow or other object) and EventBus, with Ready / Not ready from their conditions. Both pages appear under Tools and say so when the CRDs are absent. Not run against a live Argo install.

- **Who and what in the audit log** (backlog 12 follow-up). Every audit entry for a change (apply, create, delete, scale, restart, resize, cordon, drain, exec, port-forward, debug containers, Secret reveals, Helm installs, upgrades, rollbacks, uninstalls and repository changes, approved MCP proposals) records the acting **User** (the OIDC email or username, else `local`) and the **Kind** as group/version/resource. The Audit Log page has a User column and shows Kind in an entry's details; the Timeline tab names an OIDC user and no longer mixes in entries about another kind with the same name. `GET /api/audit` takes `user` and `kind` filters, and with OIDC sign-in returns only your own entries (Kubebay has no admin role). Creating resources from **New resource** is now audited on success too, not only when rejected. Older log lines still read; they show no user or kind.

### Changed
- **Less work per live update on big clusters** (backlog 23, performance pass 3). A pod's row in the Pods list is worked out once per change to that pod, not again for every pod on every update, so an update where one pod changed redoes one row (measured at 2,000 pods: 2,000 derivations per update before, 0 for an unchanged update and 1 for one changed pod after). The Overview's SPOF Radar and Service Health tabs match pods and EndpointSlices to workloads and Services through an index instead of scanning every pod for each one: at 2,000 pods and 500 Deployments, Services and EndpointSlices they read pod objects 501,750 and 1,000,000 times before, 3,750 and 2,000 after. Nothing on screen changes.
- **Selected namespaces come first in the namespace filter** (backlog 55). They sit right after **All namespaces**; on clusters with Rancher projects they form a **Selected** group above the project groups. Search still works.
- **Shorter table rows.** Rows are 28px at Compact, 32px at Default and 40px at Relaxed (they were 35, 43 and 51px), so a 900px table shows 28 rows at Default instead of 20. The text now sets the height: each cell has a 20px line box plus 4, 6 or 10px of padding above and below. The row's ⋮ menu button stays 26px and sits in a cell with no padding, which it previously got by mistake. Status pills and badges in a cell fit inside the line box.
- **One table header style.** Every column header is now 13px sentence case in the muted text colour at weight 500, as sortable headers already were. The 12px uppercase headers on columns that don't sort are gone. The header row has a solid background and no longer blurs the rows that scroll under it.
- **Hovering a row only shades it.** The accent bar at a row's left edge now marks only selected rows and the row the keyboard is on (↑, ↓, j, k). A row under the mouse pointer no longer gets the bar, so it can't be mistaken for a selection. The keyboard row previously had no bar of its own. Pinned Name and checkbox cells follow the same rule.
- **No text under 11px.** At font size S the two smallest steps of the type scale are now 11px (they were 10 and 11px); the scale is 11, 11, 12, 13, 15, 18 and 28px. Monospace cells in tables (names, IPs, ages) are never under 12px: at S with Compact density they now use 12px instead of 11px.
- **Fixed band heights.** Page headers and toolbars are both 40px (toolbars were 38px), tab strips are 36px (the page tab strip was about 50px), and the status bar is 24px (it was about 29px). The heights, the table row line box, and the widths of the cluster rail (56px) and sidebar (210px) are now tokens in `tokens.css`, so the sidebar width is no longer repeated as a literal in the layout.
- **Corners by role.** Anything that tiles the window (the sidebar and its items, tab strips, tables, cards, banners, empty states, the theme cards in Settings) is square. Buttons, fields, segmented controls, keycaps, badges and status and namespace pills have 2px corners (they were 4 to 8px, and pills were fully round). Menus, dialogs, the command palette and ⓘ panels keep soft 6px corners (the palette was 14px, menus and dialogs 8px). Status dots stay round. In `tokens.css` the radius size scale is replaced by three role tokens, `--kb-radius-tile` (0), `--kb-radius-control` (2px) and `--kb-radius-float` (6px); `--kb-radius` and `--kb-radius-sm` remain only for the website.
- **No resting shadows.** Cards, primary buttons, the selected theme card and Topology's canvas and cards no longer cast a shadow or carry an inset highlight; only things that float over the page do. The `--kb-shadow-rest` token is gone from all 12 themes.
- **An opaque frame.** The cluster rail, the sidebar, the status bar and the cluster list's status bar are now one solid shade per theme, a new `--kb-bg-chrome` token declared in all 12 themes. The step between it and the page is between 1.10:1 and 1.30:1 in every theme that isn't high-contrast; where a theme's canvas already made that step, chrome is the canvas colour. They are no longer translucent or blurred, and neither is the page header, which was 60% see-through. The faint radial glow behind the app is gone. The status bar's top rule is now the brand gradient, cyan to green, at 1px. Region borders use a new `--kb-separator` token: the subtle border in normal themes and the strong border in Dawn HC and Dusk HC, where it reaches 3:1. `--kb-bg-sidebar`, `--kb-material`, `--kb-material-blur`, `--kb-glow-a` and `--kb-glow-b` are removed. To keep text readable on the new chrome, GitHub Light's subtle text is a little darker (`#656d77`, was `#6b737d`) and Dusk HC's strong border is a little brighter (white at 36%, was 34%). Dawn HC's swatch in Settings now shows its white surface.
- **Full-width sidebar items.** Sidebar items, group titles and section labels run the full width of the sidebar instead of sitting in rounded chips 8px in from its edges, and nested items are indented by their padding. The page you're on is shaded edge to edge with the 3px accent bar, at the regular weight (it was bold).
- **A flush drawer.** A drawer now stops at the top of the status bar instead of covering it, and its left edge is the separator line. Its header is 40px tall and, like its tab strip, uses the frame's chrome shade. Section titles in **Summary** are chrome bands instead of underlined labels.
- **Label and value rows in two columns.** The facts in a drawer's **Summary** (a pod, node, Service or ResourceClaim, any object's Info and annotations, and a Helm release's Release section) are now a description list: labels in a column at least 30% wide, values beside them, a thin line between rows, so a screen reader reads each label with its value. Before, each label sat at the far left and its value at the far right of the row. A ResourceClaim now leaves out a row with no value, as the others already did. The new `PropertyList` and `Property` components in `@kubebay/ui` draw them, and the shell's `.pod-kv` class is gone.
- **Cards as blocks.** Cards no longer have an outline, and an interactive card no longer lifts by 1px and casts a shadow on hover; it shades, like a table row. The theme cards in Settings shade on hover too, instead of lifting. A selected card keeps its 3px accent bar. In Dawn HC and Dusk HC, where a card is the same shade as the page, cards keep a strong-border edge, set by a new `--kb-card-edge` token (transparent in the other ten themes). The kind cards on the Overview and the chart cards in the Helm store are now 8px apart (they were 12px), laid out by a new `Grid` component in `@kubebay/ui`; the shell's `.cluster-grid` class is gone.
- **Square banners and empty states.** A banner has a 3px bar in its status colour down its left edge instead of a tinted outline all round. An empty state is a plain block, without the dashed outline.

### Fixed
- **Linux install instructions that didn't work** (backlog 58). Tested in Ubuntu 22.04 and 24.04 containers on x86_64 and arm64: `docs/INSTALL.md` downloaded from the v0.1.0 release, which has no assets, so `curl -LO` saved GitHub's "Not Found" page and `tar` failed with `gzip: stdin: not in gzip format`; the checksum step used `shasum`, which a stock Ubuntu doesn't have (`shasum: command not found`); no page said how to install the `.deb`, and `sudo dpkg -i Kubebay_0.8.0_amd64.deb` stops with `dependency problems prevent configuration of kubebay` (`libwebkit2gtk-4.1-0`, `libgtk-3-0`) and leaves the package broken, while `sudo apt install ./Kubebay_0.8.0_amd64.deb` installs and starts; and nothing said the AppImage needs FUSE 2. The install page, `docs/INSTALL.md`, the README and the site's Download section now give the install script, `apt install ./…deb`, `sha256sum -c`, the AppImage's `libfuse2t64` / `libfuse2`, and say there's no ARM64 desktop app. They also no longer say Homebrew installs the macOS desktop app: the formula installs the engine. The Windows engine is a `.tar.gz`, not the `.zip` `docs/INSTALL.md` named.
- **The release's Homebrew tap update** wrote formula URLs without the tag's `v` (`releases/download/0.8.0/…`) and `sha256 "LINUX_PLACEHOLDER"` for Linux, and failed every release with a 403 because `GITHUB_TOKEN` can't push to the tap repository. It now uses `v#{version}`, the Linux tarballs' real checksums, stops if any checksum is missing, pushes with a `HOMEBREW_TAP_TOKEN` secret and skips with a warning when that isn't set.
- **Cmd/Ctrl+K opens the command palette from inside a YAML editor** (backlog 53). Monaco kept the key for its own chords (comment, fold) and the palette never saw it; every editor now passes it on, in the drawer, Create Resource, the dock and the Helm and KEDA previews.
- **DaemonSets no longer all count as issues on the Workloads Overview.** Their card counted every DaemonSet as unhealthy because it looked for Deployment fields; it now compares ready pods with the number the DaemonSet should run (`numberReady` against `desiredNumberScheduled`).

### Security
- **On a shared engine one user can't change another user's Helm repositories, and usage history stays off with OIDC** (internal security review, follow-up). In a cluster or with OIDC sign-in, `POST /api/helm/repos/add` and `POST /api/helm/repos/remove` answer 403 with the reason when they would add, repoint, change the credentials of or remove a repository. Before, one user could point an existing repository name at their own server and so choose where another user's `repo/chart` installs came from. Re-adding a repository exactly as configured and refreshing indexes still work. The operator lists repositories with the chart's new `helmRepos` value or `--helm-repos` / `KUBEBAY_HELM_REPOS` (`name=url,name=url`), which the engine writes into its Helm config at startup. Usage history was recorded under the engine's own identity, and served to every user, when OIDC was on but the engine was not in a cluster; it is now off whenever OIDC is configured, and `PUT /api/history/recording` and `DELETE /api/history` answer 403 there. `GET /api/settings` reports `helmReposLocked`. The Settings page shows a banner with the reason and turns off the fields and **Save** buttons it can't change; the Helm store hides **Add repository** and **Remove repository** and says why. The desktop app is unchanged.
- **A shared engine no longer goes past each user's RBAC** (internal security review). In a cluster or with OIDC sign-in: the settings that apply to every user (the node shell and debug images, the Prometheus URLs and pinned Prometheus Service, and kubeconfig sources) are read-only through `POST /api/settings` and `POST /api/prom/target`, which answer 403 with the reason. Saved values are ignored. Before, one user could set the image of the privileged node-shell pod that an admin's next node shell ran with the admin's credentials. The operator sets these through the chart's `nodeShellImage`, `debugImage`, `prometheus.url` and `prometheus.allUsers` values, or `KUBEBAY_NODE_SHELL_IMAGE`, `KUBEBAY_DEBUG_IMAGE`, `KUBEBAY_PROMETHEUS_URL` / `--prometheus-url` and `KUBEBAY_PROMETHEUS_ALL_USERS` / `--prometheus-all-users`. Raw PromQL from an OIDC user reaches the engine-wide Prometheus URL only once the operator turns on `prometheus.allUsers`; until then it goes through the API server's service proxy as that user. `GET /api/waste/workloads` (Cost / Waste's workload usage), which the engine measures under its own identity, now shows an OIDC user only the namespaces where a SelfSubjectAccessReview says they may list pods, and nothing if the check fails. The desktop app is unchanged. The docs now say that the in-cluster audit log is on a 64Mi `emptyDir` and is lost on restart.

## [0.8.0] - 2026-11-19

### Added
- **Blast-radius preview.** Delete, scale to zero, restart and Node drain confirmations have a collapsible **What this affects**: ReplicaSets and Pods involved, Services that would lose all endpoints and the Ingresses and HTTPRoutes that reach them, HPAs, PodDisruptionBudgets that would be violated, PersistentVolumeClaims kept, Pods nothing recreates, and a warning on production-looking clusters. Built from streamed data, advisory, says unknown for anything it cannot read, never blocks.
- **Helm store: add and remove repositories, rendered README, letter avatars** (backlog 11). The Charts tab has **Add repository** (name, URL, optional basic-auth username and password; the engine checks the URL with the same SSRF guard and downloads the index before saving, and shows the refusal in the form) and **Remove repository** (confirm, deletes the cached index, leaves releases alone). `POST /api/helm/repos/add` now takes `username` and `password` and refuses names that could escape the cache directory; new `POST /api/helm/repos/remove`; both are audited. A chart's README is rendered as Markdown by a small in-repo renderer that builds elements (raw HTML dropped, images shown as alt text and never loaded, links only for http, https and mailto with `noopener noreferrer`). Cards show a letter tile (new `Avatar` in `@kubebay/ui`) instead of the chart icon, since an icon is a third-party URL the CSP forbids. Not run against a real private repository.
- **Service map: All namespaces and an observed-traffic overlay** (backlog 39, phase 3). The Service map's namespace picker has **All namespaces**: nodes are grouped by namespace, joined where a reference names a Service elsewhere, and capped at 400 nodes with a "Showing the first 400 of N, narrow by namespace" message. Its streams open without a namespace filter only while that choice is selected. When the cluster has a Prometheus (yours or auto-detected), **observed traffic (Prometheus)** asks it, only once ticked, whether `istio_requests_total` or `nginx_ingress_controller_requests` exist and draws request-rate lines labelled **observed** with the rate, the time and the PromQL; with neither metric it says **No traffic metrics found** and draws nothing. - **A closed ⌘K palette no longer costs anything.** It was mounted for the whole session and kept its own full-object pod stream open on every page, with a second in-browser copy of every pod and a row rebuilt for each pod on every update, and it polled the cluster and port-forward lists every 30 seconds. It now reads and fetches only while open.
- **A Secret's YAML no longer shows its values.** Opening a Secret in its drawer (the YAML tab and the summary) printed every value in plain base64, and its `last-applied-configuration` annotation held another copy. The values are now hidden; **Reveal values** loads them and records an Audit Log entry. Editing a Secret's labels and other fields still works while they are hidden, and a save that changes a still-hidden value is refused.
- **The Overview no longer says "Healthy" before it has looked**: right after you opened a cluster, Cluster health read *Healthy · All 0 pods healthy* and Needs attention *Nothing needs attention* for about two seconds, even on a cluster with crashing pods, because the page showed its verdict once any kind had loaded, and a 2 s throttle then held back the pods when they arrived. It now says **Checking** until the pods, workloads and nodes it judges have loaded, and gives the verdict the moment they do. When RBAC forbids listing them it says **Unknown** with the reason, never Healthy.
- **A Helm release's drawer never upgrades another release with its chart or values**: with one release open, opening another from the keyboard (Enter on its row) kept the first release's chart ref, version and edited values, so **Save & upgrade** would have installed them over the second. The chart store's install form had the same flaw: opening another chart kept the first chart's release name, version and values. Each now starts from the release or chart it opens
- **Helm releases list about 10× faster**: Helm's list fetched and decoded every revision of every release before keeping the newest. Kubebay now asks the API server only for revisions Helm hasn't superseded, with the same rows: 60 releases with 10 revisions each went from 2.3–3.1 s to about 0.2 s on a local API server. Upgrades from Kubebay keep 10 revisions, as the helm CLI does (they kept every one) (ADR 0004)
- **A drain that can't reach the cluster says why**: when Kubebay couldn't build a client from a cluster's credentials (a malformed certificate, say), Drain ignored the error, tried to cordon the node anyway and reported the cordon's failure. It now stops before cordoning and reports the client error
- **Helm: no rendered Secrets in the release list**: the release list and history sent every release's rendered manifest to the page on each 12-second refresh, Secret data included, and nothing showed it. They no longer carry manifests (the list for 60 releases went from 71 KB to 13 KB), and the Manifest tab masks each Secret's `data` and `stringData` values, keeping their keys (ADR 0004)
- **Helm acts as you**: Helm read the kubeconfig itself instead of using the connection every other request uses, so it ignored the signed-in identity and, in in-cluster mode, which has no kubeconfig, couldn't work. It now uses that connection, so in-cluster it impersonates the person signed in like every other request. Rollback and uninstall are now in the audit log, like install and upgrade
- **Helm release drawer stays current**: the drawer kept the release as it was when you clicked it, so after an upgrade, a rollback or a failure elsewhere its Rollback buttons pointed at the wrong revision. It now follows the release live, refreshes its history when the release moves on, and says when the release has been uninstalled. History lists the newest revision first (it read v1, v10, v2…)
- **The engine uses far less memory on big clusters**: watching 100,000 pods, it held about 2 GB, five times the PRD's 400 MB budget, and grew while nothing changed. A heap profile found three causes, now fixed:
  - managedFields' field sets, which nothing in Kubebay reads, were most of every object in memory (each entry's manager and time stay);
  - the Cost/Waste sampler fetched every pod in one request every minute, even with the page closed; it now fetches 2,000 at a time;
  - a table's first load copied every object before sending the first, and the cluster's initial list was also sent ahead of it, copied a second time. It is now sent 200 objects at a time, each object once.
  
  The same 100k pods now stay under 400 MB in metadata mode (346 MB at sync, 389 MB once the sampler has run), and at 1.4 to 1.9 GB in full mode, which the Pods page uses, down from 2.6 to 3.2 GB. Tables loaded in metadata mode send about 75% less on first load and sync about twice as fast
- **The Overview's SPOF Radar and Service Health tabs load their data**: a stream that starts switched off (these tabs' PodDisruptionBudgets, Services, EndpointSlices, Ingresses and kube-system ConfigMaps open only when the tab does) never subscribed when it was switched on, so the tabs judged a cluster without them
- **Long tables scroll smoothly**: scrolling the Pods table with 100,000 pods ran at about 37 frames a second in the performance harness. Every row's Age tooltip built a new date formatter, and the select-all box checked every row on every frame, even with nothing selected. It now runs at 55 to 59, against the browser's 60 there. Every resource table shares this code, so they all gain the same
- **A list filtered to several namespaces shows all of them**: picking `shop` and `payments` showed only whichever namespace loaded last, because each namespace's rows replaced the others'. A subscription now arrives as one snapshot holding every namespace. When RBAC refuses one of them, the list says so ("You can't list deployments in payments. Showing shop.", with the API server's reason) and the rest stay live; before, one refused namespace stopped the whole list while its rows stayed on screen marked Live. AI assistants (MCP) asking for something RBAC refuses get the refusal at once instead of a 20-second timeout
- **The container image reports its version**: `kubebay --version` and `/api/version` in the `ghcr.io/rajasardar/kubebay` image said `dev`. A release's image now reports its tag, like the release binaries, and a main build reports `main-<commit>`. The image's engine is also built by the Go release go.mod names (1.26.9), as the release binaries are, instead of whichever Go 1.26 Docker Hub had at build time
- **The local terminal works in released desktop apps**: the release workflow built the desktop app's engine without the `localshell` build tag, so on macOS and Linux the terminal for your own machine said "local shell is not built into this binary" in every downloaded app; only `make build` builds had it. The desktop engine is now built with the tag on every platform (the standalone engine and the container image still never have it). CI's desktop smoke test starts the engine it builds with `--local-shell` and fails unless the shell is available, or, on Windows, which has no local shell, unless the engine gives the platform's own reason
- **Helm installs put every object in the release's namespace**: installing or upgrading a chart from the Helm page put any object whose template has no `namespace:` into the kubeconfig context's namespace (usually `default`), while the release itself was recorded in the namespace you picked. `helm install -n` puts them in the release's namespace, and so does Kubebay now. Charts that template `namespace: {{ .Release.Namespace }}`, as most published charts do, weren't affected
- **Kubebay no longer uses CPU while you're not doing anything**: with a cluster page open, the engine woke every open table's update queue 60 times a second whether or not anything had changed, about 5% of a CPU core on a quiet cluster. The CI performance job flagged it against the PRD's "≈ 0% idle CPU". A table's queue now sleeps until a change arrives and sends it 16 ms later, as before, and the same page now costs about 0.1%
- **Nothing loads from Google any more**: every launch fetched a stylesheet from fonts.googleapis.com, for Inter (which nothing used) and JetBrains Mono (Display settings' third font), telling Google each time Kubebay opened; offline, JetBrains Mono quietly fell back to another font. JetBrains Mono now ships with the app, and the page loads nothing from another origin (a test checks `index.html` and that every font Display settings name is bundled)
- **The YAML editor works offline**: every code editor (YAML tabs, Create resource, Helm values, the KEDA and right-sizing diffs) loaded Monaco from cdn.jsdelivr.net the first time it opened, so with no internet, behind a proxy that blocks it, or in an air-gapped install it never appeared, and each first open told a CDN you were using Kubebay. Monaco now ships in the app: the editor, its features and YAML only, about 4 MB minified, loaded the first time an editor opens. Closing a diff (after Dry-run, or turning off "diff view") no longer throws an uncaught "TextModel got disposed" error
- **Pages that can't read what they need say so too**: the Workloads Overview, Timeline, Right-sizing and Cost / Waste kept their loaders up forever when RBAC didn't let your identity list what they read. Each now says what it can't list ("You can't list pods, nodes, deployments, statefulsets, daemonsets and jobs here.") with the API server's reasons
- **A list you're not allowed to see says so**: when RBAC doesn't let your identity list a kind (say, Deployments across all namespaces), the page said nothing and showed a loading table forever, while the engine retried the list in the background. The engine now stops asking and the list says "You can't list deployments here." with the API server's reason. Opening the page again, for example after your access changes, tries again
- **A Deployment's Rollout tab finds its ReplicaSets again**: the drawer's copy of an object had its `uid` and creation time stripped like the YAML editor's, so the Rollout tab always said "No ReplicaSets found", the Timeline had no rollout revisions, and Summary's Created read "–". Only the editor's YAML leaves them out now
- **Dialogs say what they are**: `Modal` takes a `title`, shown as the dialog's heading with a Close button beside it, and centred dialogs taller than the window scroll inside instead of running off it. Configure Prometheus, Scale and Restart, Remove from list and Kubeconfig sources use it; the first had no visible heading at all
- **Configure Prometheus dialog**: the URL field, Cancel and Save show at once instead of waiting behind a spinner that never ended when the cluster's Services could not be listed. It no longer connects a cluster just to look for services, and is not offered for a broken kubeconfig entry. It opens on the URL already set; saving it empty goes back to the default. It lists the Prometheus server first, without Grafana, Alertmanager or exporters (at most four). A service on port 80 gets `localhost:9090` and `port-forward 9090:80`. Enter saves, the engine's own save error is shown, and the dialog is wide enough for a URL and its port-forward command
- **Clusters page**: it no longer opens blank (`HEADERS is not defined` after the v0.5.0 version bump), and its row menu items work again. A pressed row's scale effect moved the menu mid-click, so no item ran; `ContextMenu` now renders into `document.body`, as `Modal` does
- Tables sorted counts as text, so a Job with 10 failures sorted below one with 9 (also Restarts, node Pods, event Count). Every table now sorts numbers as numbers and names naturally (pod-9 before pod-10), ignoring case
- The Pods table mounted every row (5,000 pods meant 5,000 rows); it now renders only the rows in view, like the other tables. Every table also estimated rows 6px too short, which left the active row half off-screen after a keyboard move and made the scrollbar jump
- Pods' CPU and memory bars measured every pod against 1 core and 1 GiB, and memory was always drawn in the warning colour. Bars now measure against the pod's own limit (warning at 80%, error at 100%), or its request when it has no limit, and the tooltip says which
- Ages in tables went stale: a pod created "5s" ago still read "5s" a minute later, because rows only re-render when their data changes. Age cells now keep counting, from one shared clock
- Tables could stay on their loading skeleton forever on a fast cluster, and a table could briefly show another resource's rows (StatefulSets showing Deployments): stream frames were handled out of order
- Pods never showed "live" and did not load CPU/memory on a second visit
- The + button on resource tables did nothing; the row menu's "Edit YAML" opened the summary
- The Create Resource dry-run toggle label used an undeclared colour token; it now uses the muted text colour
- Every size, radius, animation duration and stacking layer in the app comes from the design tokens, so the command palette, context menus, drawers and dialogs always stack in the same order
- Borders, focus halos, text colour and backgrounds missing in the Network Policy view, cluster picker and cluster detail drawer: six undefined `--kb-*` variables now point at real tokens (#12)
- Cluster-picker nav highlight and engine-status dot follow the theme instead of fixed colours (#12)
- ArgoCD sync and health pills had no background or border (their colour was built as invalid CSS)
- Two notices styled with an `info-banner` class that had no CSS now render as proper banners
- Light-theme users no longer see a dark frame on launch: the saved theme is applied before first paint
- Text inputs and selects have a visible edge in every theme (3:1, WCAG 1.4.11) via a new `--kb-border-control` token; before, it measured 1.1–1.8:1
- Focus rings, selected rows and status dots stay visible in Windows High Contrast (forced colours)

  - Table loading states drew nothing: skeleton blocks were inline spans with no size inside table cells. They are now visible blocks on every ground
  - Pill, badge, active-segment and palette text fell below 4.5:1 on canvas, raised and inset grounds and on selected rows in up to nine themes. Tints are lighter, pill text is adjusted per theme, and Dawn, VS Code Light+, GitHub Light and Nord have a slightly deeper accent
  - Cluster avatars: the AWS preset (`#F90`) and unknown clusters showed white labels on light colours (1.9:1); inactive clusters in the strip were faded to 32%, taking labels to 1.3:1. Labels pick their colour correctly and inactive avatars are desaturated instead of faded
