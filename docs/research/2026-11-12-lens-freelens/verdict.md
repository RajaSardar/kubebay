# Verdict: Kubebay vs Lens vs Freelens (adversarial review, 2026-11-12)

Wording rule used throughout: another tool is "not documented" or described by what its pages say. Never "lacks".
"Confidence" = confidence that the safe wording in the row is true and supported by a primary source I re-read, not confidence that the feature is absent from the app.
Kubebay verdicts come from kubebay.md; the three most serious "soften" findings were re-checked in code (section 1, items 7-10).

## 1. Disagreements found and how each was resolved

1. **Lens MCP server plan (pricing page vs docs vs lens-b).**
   lens-b said pricing lists "Built-in MCP Server" under Pro and docs say Plus+. Re-read https://lenshq.io/pricing today: the feature table ticks "Built-in MCP Server" for Plus, Pro and Enterprise (Personal not ticked). Re-read https://docs.lenshq.io/k8slens/mcp-server/ and /mcp-server/getting-started/: "Plus, Pro, or Enterprise subscription plan"; the server runs "read-only kubectl commands". There is no conflict now. lens-b's "Pro" was a mis-read (or an older page). **Resolved: Plus or higher.** Kubebay's own site is wrong: `website/src/data/comparison.ts` ~line 232 says "Pro plan: built-in MCP server" (fix to Plus). Same fetch shows Ask AI, Security Center, Cost Monitoring, GitOps and cloud integrations all start at Plus.

2. **Freelens topology (Resource Map).** freelens-b: official extension provides a topology graph. The site's comparison.ts row "Namespace topology graph" says Freelens "Not documented". Re-read https://github.com/freelensapp/freelens-resource-map-extension: owned by freelensapp (also in the official marketplace extensions.json as `@freelensapp/resource-map-extension`, status "official"), MIT, "displays Kubernetes resources and their relations as a force graph" of Pods, Deployments, StatefulSets, DaemonSets, Services, Ingresses, ConfigMaps, Secrets, PVCs and Helm releases; read-only (list/watch only); Freelens 2.x (v2.0.0 released 2026-11-01). ReplicaSets are not in the list the README gives. **Resolved: freelens-b is right; the site row is wrong.** Topology is not a standout row. Kubebay's difference is only that it is built in and includes ReplicaSets.

3. **Freelens Karpenter.** freelens-b: official, read-only, "spot vs on-demand and unschedulable pods not confirmed". Re-read https://github.com/freelensapp/freelens-karpenter-extension: freelensapp-owned, MIT, "reads the Karpenter objects, the nodes, the pods and the events of the cluster, and writes nothing to it"; treemap shows "each node's status and capacity type (spot or on-demand)"; Overview tracks "NodeClaims still waiting for a node"; releases v2.3.0 and v2.3.1 (2026-11-06, 2026-11-10). **Resolved:** view parity on spot/on-demand and pending NodeClaims; the only documented difference is Kubebay's NodePool editing with eviction warnings (Freelens's is read-only). It is not in marketplace extensions.json (11 entries) but is in the org.

4. **Freelens KEDA (freelens-a "official but being set up" vs freelens-b "community works").** Re-read https://github.com/freelensapp/freelens-keda-extension (README: "This repository is being set up"; 1 commit, no releases) and https://github.com/nidiodolfini/freelens-keda-extension (community, owner nidiodolfini, 27 commits, "browse ScaledObjects, ScaledJobs, TriggerAuthentications...", pause/resume, Freelens ^2.0.0). **Resolved:** no released official KEDA extension; a working community one exists. Neither documents HPA-conflict detection, a creation wizard or unused-TriggerAuthentication detection. KEDA is "extension exists (community)", not "not documented".

5. **Freelens Argo CD (who owns it, login).** Re-read https://github.com/Sebastian-Prokesch/freelens-argocd-extension: owner is an individual, MIT, requires Freelens ^2.0.0, adds an "Argo" section for Argo CD, Rollouts and Workflows; context menu has refresh, hard refresh, sync; "Drift Hotspots"; it reads Application CRDs through the cluster by default, with optional remote Argo CD server config (bearer token). So an Argo CD login is not required by default. It is not in the freelensapp org and not in the marketplace JSON. Site cell (comparison.ts line 189) says "Not documented" and cites only org extensions; true to its note but misleading as a label. **Resolved:** word it "no official extension; a community Argo CD extension exists".

6. **AgentBridge / AI / "MCP-capable".** freelens-b said these are MCP-capable. Re-read: AgentBridge README (https://github.com/freelensapp/freelens-agentbridge-extension) does not mention MCP; it is an agent harness, "read-only commands run immediately, anything that changes the cluster waits for your approval". The AI extension (https://github.com/freelensapp/freelens-ai-extension, in marketplace as official) says "We support MCP Agent through a dedicated configuration. The MCP servers run in the main process of Freelens, one set per cluster" and has an approval gate. The Claude extension (https://github.com/freelensapp/freelens-for-claude-extension) has Read-only / Approve / Accept-all modes per cluster and opt-in user MCP servers. **Resolved:** these are MCP clients/agent chat inside Freelens; none is documented as Freelens exposing an MCP server to outside assistants. The site's "Claude chat, not an MCP server" is accurate but incomplete: add the AI extension and the Claude "accept all" mode. The "MCP-capable AgentBridge" claim is not supported.

7. **Secret values (F76, audit "soften").** Opened `engine/internal/httpapi/yaml.go` HandleGetYAML (lines ~109-160): it fetches the object and marshals it with only `stripNoisyFields`; grep for "secret" in yaml.go, YamlTab.tsx and GenericDrawer.tsx finds nothing. **Confirmed:** a Secret opened in the drawer shows `data` unmasked, with no click-to-reveal and no audit entry, while `website/src/content/docs/security.md:28` and the Secrets section imply masking ("stays masked until you click" refers to env vars only). "Never loaded into tables" is true; do not extend it.

8. **Default-container annotation (F31).** freelens-a: Freelens respects `kubectl.kubernetes.io/default-container` (release v1.10.3). Kubebay audit: not implemented. Grep for `default-container` across web/, engine/, website/src, docs/ finds only `docs/PARITY_FRELENS.md:37` (listed as a goal) and line 110. **Confirmed not implemented.** Remove from the F31 claim; Freelens has it, so this is a Kubebay gap, not an advantage.

9. **Helm release in the Owned-by chain (F23).** grep "helm" in `useOwnerChain.ts`, `PodSummary.tsx`, `MetadataSummary.tsx`: no matches. `website/src/content/docs/pods.md:27` still gives "Helm release -> Deployment -> ReplicaSet -> pod". **Confirmed docs overstate.** Freelens has "Controlled By" (immediate owner only, per source) and its official Resource Map extension relates pods to Helm releases; Lens shows "Controlled By" in the pod table. Do not claim a unique full chain.

10. **Cosign and air-gap bundle: v0.7.0 or v0.8 (F77/F78).** `gh release view v0.7.0` lists `kubebay-airgap-v0.7.0.tar.gz`, `kubebay-airgap-v0.7.0.tar.gz.cosign.bundle`, and a `.cosign.bundle` beside every asset (dmg, exe, deb, AppImage, tarballs, sbom, install-mac.sh). tauri.conf.json is 0.7.0; tags go to v0.7.0. **Confirmed shipped in v0.7.0.** Docs still say v0.8: `install.md:94` and `air-gapped.md:9,14-60`. Also `.sha256` exists only for the five engine tarballs (and their `.sha256.cosign.bundle`), so "Every release asset has a `.sha256`" (install.md:94) is overstated. I did not run `cosign verify`; the audit did not either.

11. **Lens "open source" (lens-b conflict between two summariser fetches).** Re-read https://github.com/lensapp/lens: MIT licence on legacy code, but "the open source version of Lens Desktop has been retired and is no longer maintained"; community contributes through extensions. https://docs.lenshq.io/faq/subscription-and-licensing/: "All Lens users will need to create a Lens ID in order to activate Lens K8S IDE"; offline activation exists via Lens ID; Personal is for orgs under USD 10M revenue or funding. The FAQ says larger orgs "must purchase Lens Pro", while the pricing page says "paid subscription" (plan not named): minor internal inconsistency in Lens's pages. **Resolved:** say "Lens's docs say a Lens ID is needed to activate; Lens's GitHub says the open-source version is retired". Do not say Lens is or is not open source; telemetry default unverified (Preferences has a Telemetry toggle).

12. **Lens details-panel NOT-DOCUMENTED rows (thin check, F24/F25/F27/F34/F37/F44).** Re-read https://docs.lenshq.io/k8slens/using-lens/details-panel/: it documents only three universal actions (Copy name, Edit, Delete) and says per-resource content is on each resource page; it does not itemise tabs or sections. **Resolved:** these rows cannot be backed by "docs do not mention" as evidence about the panel. Downgrade them to "the docs do not itemise the details panel" and send to human check (section 4). Only rows where a whole page/menu would be expected (menus, sitemap pages) keep NOT-DOCUMENTED.

13. **Lens Network Policies page (F55-F57).** Re-read https://docs.lenshq.io/k8slens/using-lens/network/network-policies/: columns Name, Namespace, Policy Types, Age; actions Edit and Delete; search, column resize/reorder/visibility, CSV export; clicking a row opens a details panel (content not itemised). Nothing on a matrix, reachability or a builder. **Resolved:** Lens has a list; matrix, coverage, evaluator and builder are not documented. Freelens has a list plus per-policy details with Ingress/Egress rules (source, freelens-b); marketplace and org have no network-policy extension, GitHub repo search for "freelens network policy" returned nothing. Kubebay's list (F55 half) is parity; the matrix, F56, F57 are the differentiators.

14. **Freelens extension marketplace vs missing items.** Re-read https://raw.githubusercontent.com/freelensapp/freelens-marketplace/main/extensions.json: agentbridge, ai, fluxcd, kamaji, resource-map (official); jobset, duplicate, version-update, multi-pod-logs, resource-filter, certificate-info (community). The org has 30 repos incl. gpu, karpenter, keda, sveltos, velero, cnpg and others. Nothing for network policy, SPOF, upgrade/deprecation, attack paths or general cost (gpu has "Idle & waste" for GPUs only). GitHub search found community Trivy-Operator extensions (hellboyhha, johnvox, DiegoBulhoes; v1.x badge, v2 compatibility unverified) and a community workload-topology extension (agent-jeong/freelens-workload-topology). **Resolved:** the site's Freelens "Not documented" for CVE view should say "community Trivy-Operator extensions exist".

15. **freelens-a vs Kubebay claims of uniqueness (F34, F37, F39, F31).** Freelens source/releases show pod resize (v1.9.0), force delete/finalizers (v1.6.0), node shell with the same privileged pod + nsenter, default-container. Lens docs are silent on F34/F37 but the panel is not itemised (item 12). **Resolved:** none of F31, F34, F37, F39 is a Kubebay-only feature; F34 is also CODE-ONLY (no test).

16. **Kubebay inventory lines that overstate (audit "Claims to soften")**, accepted after sampling: F01 (no session age), F02 (resizable columns unreleased; "star" is a pin menu), F22 (webhooks only, not native VAP denials), F28 (not server-side apply), F46 (not an Artifact Hub store), F47 ("Hard Sync" = annotation `refresh: hard`; matches argocd.md:19), F54 (table stops at K8s 1.29), F59/F69 (typed confirmation, not one click), F62 (six preset checks), F66 (CIS + MITRE labels only), F72 (Windows/Linux labelled Preview, `install.md:35`). Note the site itself is inconsistent: `install.md:11` says "A native window on macOS, Windows and Linux" while `install.md:31-35` says Preview. UNRELEASED parts (F02 resize, F11 CRD star, F14 copy-name, F30 Pod IPs, F67 Paused/search/All, F23 CRD owners) are post-v0.7.0: public claims must say "in main, next release".

17. **"No phone-home" (F75).** security.md:44 and air-gapped.md:9 say no phone-home; the desktop app does an update check to GitHub (daily, on by default, `desktop/src-tauri/src/updater.rs`; security.md table row "An update check"), though v0.7.0 shipped without an updater key. Not telemetry, but wording should be "no telemetry, no account, no licence server" and not "no phone-home" without the caveat. Freelens: MIT, no account, sentry/telemetry removed (issue #234), one npm registry version check (source). Lens: Lens ID needed.
